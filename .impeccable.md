## Design Context

### Users

Three concrete audiences share this surface — design must serve all of them without watering down for any one:

- **Academic historians & researchers**: come for primary sources, citations, bibliography. Reading-heavy. Expect provenance, dates, authors, and stable URLs they can quote in a paper. Sessions can be long and focused.
- **GIS / data professionals**: come for datasets, taxonomies, spatial extents, time tags. Want the schema visible. Will follow links to raw data.
- **Generally curious public**: come to browse, not to query. Will leave fast if the surface looks like an ETL admin panel.

The shared task is **finding** — finding the right source, the right dataset, the right region, the right century. The pain point the project was built to solve was that the existing search experience felt like guessing in a stranger's vocabulary. The interface must make discovery feel literate rather than transactional.

### Brand Personality

Three words: **scholarly, civic, humanist.**

- **Scholarly** — careful with names, dates, and citations; comfortable with footnotes; treats the reader as informed.
- **Civic** — open-data manners. The data is the subject, not the chrome. Provenance and methodology are always one click away, never hidden behind a marketing layer.
- **Humanist** — written and laid out by people, for people. Plain prose over jargon. Warmth without whimsy. History as narrative, not as a payload.

Emotional goal: the visitor should feel like they walked into a well-run public archive — quiet, generous with space, confident about what it knows and honest about what it doesn't.

### Aesthetic Direction

Anchor reference: **Pudding / NYT graphics — editorial data journalism.** Confident typography doing most of the hierarchy work, generous whitespace, narrative flow rather than dashboard density, charts and tables that look authored rather than auto-generated.

Theme: **light and dark, both first-class.** Respect `prefers-color-scheme` AND expose a manual toggle in the app shell (persist the choice). Design dark as a sibling of light, not as light inverted — adjust chroma at extreme lightness, tighten line-height in light-on-dark, retune accent saturation.

Anti-references:
- **Not a dashboard.** No metric tiles, no sparkline decoration, no card-grid-of-cards.
- **Not a Material default.** Keep `@angular/material` as a behavior layer (tree, toolbar) but override its visual identity. Indigo/pink M3 defaults are out.
- **Not a marketing site.** No hero gradients, no glassmorphism, no oversized rounded icon-above-heading templates.
- **Not "AI tech."** No cyan-on-black, no purple→blue gradient text, no neon accents.

Texture cues that fit (use sparingly): rule lines as structure (1px hairlines, sometimes double rules), small-caps for category labels, drop caps on long-form pages, numerals tabular in tables and proportional in prose, footnote-style superscript references where there's a citation, period-appropriate ornaments only when they belong (e.g., a fleuron between sections in Methodology).

### Design Principles

1. **Type is the chrome.** Hierarchy comes from a real modular scale (≥1.25 ratio) with clear weight contrast, not from cards, shadows, or background tints. Pair a literate display face with a refined, readable body face — neither from the reflex list (no Inter, Fraunces, Newsreader, IBM Plex, DM Sans/Serif, Instrument, Space Mono/Grotesk, Outfit, Plus Jakarta, Crimson, Cormorant, Playfair, Syne).
2. **Editorial pace.** Vary spacing for emphasis. Long-form pages (Intro, Methodology) read like a magazine column with a max measure of ~70ch; index/list views are denser but still left-aligned and rhythmical. No symmetrical centered layouts as a default.
3. **Provenance is part of the design.** Every source, dataset, and area shows where it came from and when it was added. Don't hide the methodology link, don't bury "added by" metadata, don't fake confidence with rounded chips that obscure the source.
4. **Both themes designed honestly.** Light = warm paper, ink-dark text, hairline rules. Dark = ink-blue or ink-graphite surface (not pure black), bone-white text with raised line-height, accent chroma reduced. Tint neutrals toward the brand hue in both modes.
5. **Behavior over decoration.** Motion exists for state changes (route entry, tree expand/collapse, theme toggle), never as ambient sparkle. One well-orchestrated reveal beats ten micro-animations. Respect `prefers-reduced-motion`.
6. **Plain English, every label.** Replace Material's leftover `aria-label="Example icon-button with share icon"` boilerplate. UI copy is written, not generated — short, specific, never marketing-voiced.

### Implementation Constraints (project-specific)

- Angular 21 standalone components. New code uses `@if` / `@for` / `@switch`, not `*ngIf` / `*ngFor`.
- Strict mode is off in `tsconfig.json`; new code should still write typed signatures.
- Material is the behavior library only — theme via `@include mat.theme(...)` in `src/styles.scss`. Available M3 palettes in v21 do **not** include indigo or pink; current theme uses `$violet-palette` / `$rose-palette` as the closest substitutes and may be replaced by a custom palette tuned to the brand hue.
- Bundle budgets: 2 MB initial warn / 5 MB error; per-component-style 6 KB warn / 20 KB error. Web fonts and theme CSS go in global `styles.scss`, not per-component.
- Font Awesome 5.15.3, Roboto, and Material Icons are loaded from CDNs in `src/index.html`. If we change body type, retire Roboto from `index.html` to avoid a wasted preconnect.
- No tests exist. Don't claim a UI change "works" without running the dev server (or the production Docker image) in a browser and exercising the screen.
